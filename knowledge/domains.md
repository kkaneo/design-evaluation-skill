# 通用评价领域（L1）· D1–D6

> 知识库三层结构的顶层；L2 任务化视角为动态组装结果（不设固定模块），L3 评价条目见 `criteria/`
> 命名约定：论文与研究表述用「多视角（Multi-Perspective）」，技术实现用「评价条目（Evaluation Criterion）」——"视角"强调评价立场与目标，"条目"便于执行、检索、引用与验证

## 三层结构

```
L1 评价领域（跨 UI 类型复用，D1–D6，相对稳定）
 └─ L2 任务化视角（针对当前任务的问题组，每次评审动态生成，设计师确认）
     └─ L3 评价条目（可执行检查单元，criteria/ 中的 YAML 文件）
```

L2 的生成机制：任务输入 → 检索命中 L3 条目（`applicable_context`）→ 按 `evaluation_goal` 聚类为 L2 候选视角 → 覆盖检查（不足则 AI 生成新维度候选，须溯源）→ 设计师确认。若现有条目覆盖不足，AI 可生成新维度候选，最终确认权在设计师。

## D1–D6

| 领域 | 主要研究依据 | 可形成的评价条目 |
|---|---|---|
| D1 用户任务与可用性 | Nielsen 10 Usability Heuristics；ISO 9241-11 | 任务成功、系统反馈、操作一致性、错误恢复、操作效率 |
| D2 用户认知与体验 | Nielsen 启发式原则；HCI 认知负荷与信息处理研究 | 信息理解、记忆要求、选择负担、感知控制 |
| D3 产品目标与用户行为 | WiserUI-Bench | 目标行动可见性、行为阻碍、转化路径、业务与用户目标一致性 |
| D4 信息与视觉表达 | PRISM；UXBench | 视觉层级、可读性、布局关系、遮挡、信息一致性 |
| D5 无障碍与包容性 | WCAG 2.2 | 文字对比度、可操作目标、表单标签、错误提示 |
| D6 技术与交互状态 | Figma Prototype Actions；交互状态设计原则 | 状态转移、操作反馈、异常流程、撤销与恢复 |

## 两条能力边界声明（条目设计时必须继承）

- D2 的认知负荷**不能**通过界面截图直接测量——相关条目只能产出 E2 设计假设，经 E3 用户实验验证
- D3 的真实转化率**不能**凭 AI 判断——WiserUI 类基准可提供案例视角，但模型预测不等于真实转化结果
