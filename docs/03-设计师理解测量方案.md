## 1. 测量的目的

Study B 的核心因变量除了"改版方案质量"，还有"设计师是否真的理解了评审为什么这么说"。

**精确表述**：不是只证明"理解分析能力变强了"，而是证明——方案变好是因为**理解了问题与取舍逻辑**（能力提升，可迁移），而不是因为**照抄了 AI 建议**（表面效果，不可迁移）。若不测理解，Skill 的价值主张（帮助设计师理解复杂评审）就无法与"高级复制粘贴工具"区分开。

## 2. 主要混淆：表达格式 ≠ 分析能力

C3（完整 Skill）组看过 QOC 结构化输出，天然熟悉"标准答案的格式"。若评分标准偏向结构完整（有没有提到视角、冲突、取舍），C3 组会因格式熟悉而虚高——测到的是"背了模板"而非"会分析"。

## 3. 已选评分路线：内容 / 结构分离（方法 3）

评分 rubric 拆成两栏：

| 栏 | 评什么 | 用途 |
|---|---|---|
| 结构分 | 是否覆盖"问题—视角—关系—取舍"完整框架 | 单独报告，用于解释格式暴露的影响 |
| 内容分 | 事实引用是否准确、准则是否用对、推理是否成立 | **只有内容分用于检验"理解提升"假设** |

## 4. 降低作答与评分成本的题型设计

理解测试不必是长篇口头解释（效率低、依赖表达能力、很少有人说得头头是道）。三种结构化题型：

**题型 1 · 问题识别题**
给一张未评审过的设计截图，标注 top-3 问题。
→ 对照专家问题清单客观计分；天然是迁移测试（换设计出题），保留方法 1 的效度、消除口头表达负担。

**题型 2 · 关系判断题**
给出一对评审意见，从 7 种关系类型（Support / Contradiction / Complement / Trade-off / Dependency / Conditional / Uncertain）中选择，并写一句理由。
→ 客观选择题 + 一句简答；直接测量是否内化了关系框架；**题库直接复用 Study A 的金标准关系对**（如 C15×C13 Trade-off、C17×C06"相似主题≠Support"判例），一库两用。

**题型 3 · 取舍推理题**（保留 v2 的"为什么没采纳某个意见"）
短答：解释一个具体取舍的依据。
→ 按内容/结构两栏评分；对关系分析的价值最敏感。
