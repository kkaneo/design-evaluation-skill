# QOC 决策支持模板（M4 输出契约）

> QOC 用于表达设计问题、备选方案与评价理由——不做视角加权、不算综合分

## 模板

### Question · 设计问题

（一个具体问题，含目标张力；由 Trade-off 或问题聚类转化而来）

> 示例：如何在不打断付款流程的前提下，提高优惠信息的可发现性？

### Options · 候选方案

| 方案 | 可能收益 | 风险与取舍 | 证据状态 | 尚未满足的约束 | 决策 |
|---|---|---|---|---|---|
| A（原方案） | | | | | |
| B | | | | | |
| C（重构方案） | | | | | |

### Criteria · 评价准则（不加权、不求平均）

- 准则 1（来自条目 `evaluation_goal`）
- 准则 2
- ……

### 优先级输出（分级，非打分）

| 级别 | 判断原则 |
|---|---|
| P0 必须处理 | 已确认的关键任务失败、严重误操作、强约束违反 |
| P1 优先修改 | 对主要任务有明显影响、证据较充分、修改可行 |
| P2 优先验证 | 可能高收益，但存在目标权衡或证据不足 |
| P3 延后处理 | 相对低影响或与当前任务关联较弱 |

优先级顺序判断：强约束优先 → 核心任务优先 → 跨视角支持（多条目独立互补证据）→ 分歧处理（组合修改避免目标牺牲）→ 验证与实施条件。

## 四条规则

1. **不加权**：不输出"优先级 97 分"类无来源精确数字；Criteria 只做定性比较，不换算为单一分数
2. **重构方案空间**：不在既有 A / B 中二选一——利用不同视角的有效信息重组方案（分层 / 条件展示 / 按需展开是结构重组，不是各退一步的折中）
3. **Trade-off 先找兼顾结构**：存在兼顾结构则记为候选 Option；不得宣布"某视角获胜"
4. **合法结论形态**："推荐验证 C + 保留 A 作对照"，附依据与不确定性
